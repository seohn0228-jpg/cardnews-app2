# 네이버 쇼핑커넥트 블로그 원고 작성

사용자가 상품 링크를 주면 아래 순서대로 끝까지 진행한다. 중간에 확인을 묻지 말고,
막히는 단계만 대체 방법으로 넘어간다. 결과는 **발행 직전 원고**까지이고,
발행 버튼은 사용자가 직접 누른다(자동 발행은 네이버 어뷰징 정책 위반 소지가 있어 하지 않는다).

스크립트 경로: 이 파일이 있는 폴더의 `scripts/` (아래에서 `$S`로 표기).
스크립트에는 `requests`, `beautifulsoup4`가 필요하다. 없으면 `pip install -q requests beautifulsoup4`로 설치한다.
작업 폴더: 저장소 루트의 `posts/<YYYY-MM-DD>-<상품 짧은 이름>/` (`$P`로 표기).

## 0. 입력 확인

사용자 메시지에서 다음을 찾는다. 없는 것은 묻지 말고 기본값으로 진행한다.
- 상품 링크 (필수)
- 사용 후기 메모: 직접 써봤다면 느낀 점 몇 줄. **없으면 "알아본 사람" 시점으로 쓴다.**
- 직접 찍은 사진(업로드 파일): 있으면 상품 사진보다 우선해서 배치한다.
- 글 분위기: 기본값 "친근한 생활 블로거"

## 1. 상품 정보 가져오기

```bash
python3 $S/product_scraper.py "<링크>" --out $P
```
- 성공하면 `$P/product.json`과 `$P/photos/photo_NN.jpg`가 생긴다. 사진은 Read로 하나씩 열어서 실제로 무엇이 찍혀 있는지 확인한다.
- 실패하면 WebFetch로 같은 링크를 열어 본다.
- 쇼핑커넥트 링크(brandconnect.naver.com/affiliates/...)는 자바스크립트로 이동하는 중간 페이지라 정보가 없다.
  `https://gw-brandconnect.naver.com/affiliate/query/redirect/<affiliates 뒤 숫자>?channelProductNo=<번호>`에
  리다이렉트를 따라가지 않고 요청하면 Location 헤더에 실제 스마트스토어 주소가 나온다.
- 링크가 `brandconnect.naver.com/connect/<번호>` 형태(여행·서비스 상품 등)면
  `https://gw-brandconnect.naver.com/affiliate/query/connect-urls/<번호>/redirect`를 리다이렉트 없이 요청한다.
  Location 헤더에 실제 주소(예: `pkgtour.naver.com/...` 여행 상품)가 나온다. 여행 상품이면 아래 **3.5 여행 상품** 규칙을 따른다.
  여행 페이지는 모바일 UA로 Playwright에서 열고 끝까지 스크롤해 일정표·포함/불포함·취소 규정·리뷰 요약까지 가져온다.
- 스마트스토어가 429로 막히면 **먼저 네이버 선물샵 페이지** `https://shopping.naver.com/gift/products/<같은 상품번호>`를
  Playwright로 연다. 상품명·가격·리뷰·상품정보 제공고시·전성분·상세 이미지가 대부분 그대로 나온다(실제로 잘 열림).
- 선물샵이 410/"상품이 존재하지 않습니다"면 N배송 상품 페이지 `https://shopping.naver.com/logistics/products/<같은 상품번호>`를 Playwright로 연다.
  어느 주소가 맞는지 모르겠으면 `search.naver.com`에서 상품번호로 검색해 결과 링크 중 상품번호가 들어간 shopping.naver.com 주소를 찾는다.
- 선물샵도 안 되면, 네이버 검색으로 상품명을 확인한 뒤 브랜드 공식몰 상세페이지를
  Playwright(Chromium: /opt/pw-browsers)로 열어 상품정보 제공고시와 상세 이미지를 가져온다.
  이 경우 링크 상품의 가격·구성이 다를 수 있다고 결과에 꼭 적는다.
- 그래도 실패하면(네트워크 차단 등) 사용자에게 **상세페이지 글 복사본과 사진 캡처를 올려 달라고 한 번만** 요청하고, 받은 것으로 계속한다.
  이 클라우드 환경에서 네이버가 막혀 있다면, 환경 설정의 Network access에 아래 도메인을 추가하면 된다고 안내한다:
  `naver.com`, `naver.me`, `pstatic.net`

정리할 것(사실만, 근거 없는 장점 금지): 상품명, 카테고리, 가격, 장점, 스펙(용량·크기·소재 등),
누구에게 맞는지, 구매 팁(옵션·사이즈·사용 조건 등), 사진별로 보이는 내용.

## 2. 키워드 조사

```bash
python3 $S/naver_suggest.py "<씨앗1>" "<씨앗2>" "<씨앗3>"
```
- 씨앗 키워드: 상품 종류(예: 전동칫솔), 브랜드+종류, 핵심 특징+종류 등 2~4개.
- 결과의 `hits`(여러 질의에 나온 횟수)가 많고 `best_rank`가 앞일수록 실제로 많이 검색되는 키워드다.
- 자동완성이 막혀 있으면 WebSearch로 "<상품 종류> 추천", "<상품 종류> 후기"를 검색해 제목에 반복되는 표현을 모으고, 결과에 "추정 키워드"라고 표시한다.

고르는 기준:
- **메인 키워드 1개**: 2~3어절 롱테일 (예: "전동칫솔" 대신 "잇몸 약한 사람 전동칫솔"). 너무 큰 키워드는 상위 노출이 어렵다.
- **서브 키워드 3~4개**: 후기/비교/추천/가성비/사용법 같은 의도 키워드와 브랜드명. "단점" 키워드는 쓰지 않는다(사용자 지시).
- `$P/keywords.json`에 고른 이유와 함께 저장한다.

## 2.5 글 스타일 고르기 (매번 다르게)

```bash
python3 $S/pick_style.py $P
```
- 최근 글과 겹치지 않게 **구성 · 도입 · 마무리 · 말투**를 골라 `$P/style.json`에 저장하고 가이드를 출력한다.
- 원고는 이 가이드대로 쓴다. 아래 3장의 형식 예시(소제목 이름, 문장)는 **뼈대만** 참고하고 그대로 베끼지 않는다.
- 구성이 달라도 SEO 규칙(제목·첫 문단 키워드, 소제목 4~6개, 링크 안내 3곳, 사진 4~5장, 1,500자 이상)은 그대로 지킨다.
- 소제목, 첫 문장, 마무리 문장, 링크 안내 문구, 구매 팁 소개 방식은 이전 글과 다른 표현으로 새로 쓴다.
  "첫째/둘째/셋째" 나열은 체크리스트형이 아니면 쓰지 않는다.

## 3. 원고 작성

`$P/post.md`에 아래 형식으로 쓴다.

```
# <선택한 제목>

이 포스팅은 네이버 쇼핑 커넥트 활동의 일환으로, 판매 발생 시 수수료를 제공받습니다.

<도입 문단>

[사진1: 사진 아래 캡션]

## <소제목>
...

[상품 링크: 👉 지금 가격이랑 구성 확인하러 가기]

...

[상품 링크: 👉 <상품명> 상품 페이지 바로가기]

태그: #태그1 #태그2 ... (10개 안팎)
```

### 사람 냄새 나는 글 규칙
- 문장 길이를 섞는다. 짧게 끊는 문장 사이에 가끔 긴 문장을 넣는다.
- 블로그 구어체 "~더라고요", "~거든요", "솔직히", "이게 은근", "저만 그런 거 아니죠?"를 과하지 않게 쓴다.
- 첫 문단은 공감되는 상황이나 고민으로 시작한다. 상품 이름부터 들이밀지 않는다.
- **단점은 최대한 뺀다(사용자 지시, 블로그·클립 모두).** "단점", "아쉬운 점", "이런 분께는 안 맞아요" 소제목이나 문단을 만들지 않는다.
  장점·활용법·구매 팁 위주로 쓰고, 원산지는 언급하지 않는다.
- 그래도 **정확성에 꼭 필요한 조건만** 짧게, 긍정적인 "구매 팁" 말투로 넣는다(1~2줄): 숫자에 붙은 조건(예: 전기요금은 절전 모드 기준),
  알레르기·안전 주의, 옵션·사이즈 고르는 법, 여행의 취소 규정·추가 경비. 예) "전기요금은 절전 모드로 유지할 때 기준이에요", "방 크기가 10평 안쪽이면 딱 맞아요".
  이걸 빼면 숫자가 과장 광고가 되거나 구매 후 분쟁이 생길 수 있다.
- 받은 자료에 있는 구체적인 숫자(용량, 크기, 시간, 가격)를 섞는다.
- 문단은 2~4줄. 모바일 기준으로 줄바꿈을 자주 한다.
- 이모티콘은 글 전체에서 3~5개만 쓴다.
- 미리보기가 대가성 문구 위아래와 소제목(`## `) 앞마다 짧은 가운데 구분선(──────)을 자동으로 넣는다. 원고에 따로 쓰지 않는다.
- 본문은 **가운데 정렬**로 발행한다. 미리보기와 본문 복사에 가운데 정렬 서식이 들어가니, 문장은 한 줄을 짧게(모바일 기준 20자 안팎) 끊어 써야 가운데 정렬에서 읽기 좋다.
- 스펙 정리용 목록은 한 군데만 쓰고, 나머지는 문장으로 풀어 쓴다.

### 쓰지 말 것 (AI 티)
"오늘은 ~에 대해 알아보겠습니다", "결론적으로", "요약하자면", "~하는 것이 중요합니다", "다양한", "효과적인",
"완벽한", "혁신적인", "도움이 되셨기를", 모든 문단이 같은 길이와 구조인 글, "강력 추천" 반복.

### 정직하게 쓰기 (반드시 지킬 것)
- 후기 메모가 있으면 그 경험을 중심으로 1인칭으로 쓴다. **메모에 없는 경험은 지어내지 않는다.**
- 메모가 없으면 써본 척하지 않는다. "상세페이지를 꼼꼼히 봤는데", "후기들 보니까 공통적으로",
  "제가 이걸 고른 이유는"처럼 알아보고 비교한 사람 시점으로 쓴다.
- 자료에 없는 효능, 수치, 수상 경력, 판매량은 만들지 않는다. 건강이나 의학 효과를 단정하지 않는다.
- 대가성 문구는 네이버 블로그 안내(경제적 이해관계 표시)대로 넣는다.
  - 문구는 그대로: "이 포스팅은 네이버 쇼핑 커넥트 활동의 일환으로, 판매 발생 시 수수료를 제공받습니다."
  - 위치: **본문 최상단**, 제목 바로 아래 첫 줄. 글 맨 아래에 두면 안 된다.
  - 모양: 본문과 구분되게 **큰 글자나 다른 글자색**으로, 테두리 상자에 넣는다. 미리보기 페이지가 주황색 테두리 상자로 자동 표시하고, 본문 복사 시 이 서식도 같이 복사된다.
  - 블로그에 붙여넣은 뒤 상자 서식이 빠졌으면, 그 줄만 글자색(주황)과 크기를 키워 주라고 발행 방법에 안내한다.
  - 원하면 제목 맨 앞에 `[광고]`를 붙이는 방법도 있다(네이버 안내상 둘 중 하나). 기본은 본문 최상단 상자로 하고, 사용자가 요청할 때만 제목에 붙인다.

### 검색 노출 규칙
- 제목: 메인 키워드를 앞쪽에 넣고 20~40자로 쓴다. 궁금증, 비교, 숫자, 솔직함 중 하나로 후킹한다. 거짓 낚시 제목은 금지. 후보 3개를 만들고 가장 좋은 것을 `# `에 쓴다.
- **제목 후보는 두 종류로 섞어 만든다**(유입 조사 결과, 2026-11):
  - 검색형: 사람들이 실제로 치는 말 그대로 + 정확한 정보. 예) "엄공 히터 전기세, 절전 모드 기준 한 달 얼마?", "<상품> 사용법·추천 옵션 정리"
  - 홈판형: 호기심·숫자·상황 공감. 예) "히터 틀기 전에 이것부터 보세요", "64만원 패키지에 뭐가 들었나 봤더니"
  - 둘 다 메인 키워드는 앞쪽에. 키워드를 제목에 두 번 넣지 않는다(과다 반복은 노출 불이익 사례가 있음).
  - 클릭만 노리는 과장 제목은 오히려 감점된다는 분석이 많다. 제목에서 약속한 답을 본문 앞부분에서 바로 준다.
- 체류 시간과 반응이 중요하다: 결론·요약을 앞에, 표·목록으로 훑기 쉽게, 마지막에 구체적 질문을 던져 댓글을 유도한다.
- 정보의 충실함(D.I.A.): 숫자·조건·출처(상세페이지/상품정보 표)를 구체적으로 쓴다. 같은 주제를 꾸준히 쓰는 것도 노출에 유리하다는 분석이 있으니, 제목·태그의 카테고리 표현을 일정하게 유지한다.
- 메인 키워드: 첫 문단에 1번, 본문 전체에 4~6번. 억지로 반복하지 않는다.
- 서브 키워드: 소제목과 본문에 1~2번씩 나눠 넣는다.
- 본문: 공백 포함 1,800~2,500자, 소제목(`## `) 4~6개.
- 사진은 **4~5장만** 쓴다(사용자 지시: 많으면 별로). 대표 사진 1장 + 글의 핵심 포인트(차별점, 사용법/구성, 주의점 등)마다 1장씩만 고르고, 비슷한 사진이나 꾸밈용 사진은 넣지 않는다. 번호는 1부터 빈 번호 없이 매긴다.
- 사진: 본문 사이사이에 고르게, 설명하는 내용 바로 옆에 둔다. `[사진N: 캡션]`의 N은 `$P/photos`의 파일 번호이고, 캡션에는 키워드를 자연스럽게 넣는다.
- 상세페이지 이미지 중 효과 수치(%)나 전후 비교 사진은 표시광고 문제가 생길 수 있으니 고르지 않는다.

### 상품 링크 안내 넣기
읽는 사람이 어디로 들어가면 되는지 바로 알 수 있게, 링크 안내를 본문 중간중간 **3개** 넣는다.
형식은 따로 한 줄에 `[상품 링크: 👉 안내 문구]`. 미리보기에서 이 문구 바로 아래 줄에 상품 주소가 그대로 들어간다
(네이버 에디터는 붙여넣을 때 글자에 걸린 링크를 지우는 경우가 많아서, 주소를 보이게 넣어 에디터가 링크로 바꾸게 한다).
- **위치**: 읽는 사람이 "그래서 어디서 봐?" 하고 궁금해질 타이밍에 둔다.
  1. 상품 소개가 끝나고 핵심 장점을 한 번 보여 준 직후 (가볍게: "어떤 제품인지 먼저 보고 싶다면")
  2. 가격이나 구성, 구매 팁 이야기 직후 (확인 유도: "가격은 시기마다 달라서 지금 가격 확인")
  3. 맺음말 바로 뒤, 글의 마지막 (정리: "상품 페이지 바로가기")
- **흐름**: 바로 앞 문장이 링크 안내로 자연스럽게 이어지게 쓴다. 예) "할인은 수시로 바뀌더라고요." 다음 줄에 `[상품 링크: 👉 지금 할인가 확인하러 가기]`.
  앞 내용과 상관없는 링크를 툭 끼워 넣지 않는다.
- **문구**: 세 개 모두 다르게 쓴다. "구매하기", "지금 바로 구매" 같은 재촉하는 말 대신 확인·구경하는 말투로 쓴다.
  예) "👉 상세페이지 직접 보러 가기", "👉 지금 가격이랑 구성 확인하기", "👉 프라엘 써마샷 상품 페이지 바로가기"
- 링크 안내의 👉는 이모티콘 개수(3~5개)에 세지 않는다.

## 3.5 여행 상품(패키지·투어·숙소)일 때

쇼핑 상품과 글 구조가 다르다. SEO 규칙(제목·첫 문단 키워드, 소제목 수, 사진 4~5장, 링크 안내 3곳)과 정직 규칙은 그대로 지킨다.

- **구성**: 한눈에 보는 여행 정보(기간, 항공편·시간, 숙소, 식사 횟수, 팁·쇼핑·선택관광) → 일차별 코스 → 예약 전 볼 것 → 어떤 여행자에게 맞는지.
  `pick_style.py`의 도입·말투만 참고하고, 구성은 일차별 흐름을 기본으로 한다. style.json에 `"종류": "여행"`을 적는다.
- **반드시 넣을 사실**: 출발일 기준 가격(출발일마다 다르다고 적기), 항공사·출발/도착 시각, 호텔 이름, 포함/불포함,
  추가 비용(싱글 차지, 팁, 선택관광, 쇼핑 횟수), 예약금, 무료 취소 마감과 수수료, 최소 출발 인원·출발확정 여부, 긴 이동 구간.
- **단점 대신 짧은 "예약 팁"**: 추가 경비(팁·싱글 차지), 취소 규정, 여권·서류처럼 예약에 꼭 필요한 사실만 3~5줄로. 긴 이동·쇼핑 횟수 같은 건 일정 소개 안에 사실로만 적고 단점처럼 강조하지 않는다.
- **정직**: 다녀온 척 쓰지 않는다("알아본 사람" 시점). 축제·일루미네이션·날씨처럼 상품이 보장하지 않는 건 "출발 전 따로 확인"으로 쓴다.
  리뷰는 평점·개수·많이 고른 키워드만 인용하고, 개인 리뷰 사진은 쓰지 않는다.
- **사진**: 여행사가 올린 관광지·호텔·식사 사진에서 일정 순서대로 4~5장 고른다.
- **링크 문구 예**: "👉 일정표 전체 보기", "👉 출발일별 가격이랑 잔여석 확인하기", "👉 예약 페이지로 가기".
- **키워드 예**: "<지역> 패키지", "<지역> 여행 코스", "<지역> 온천여행", "겨울 <지역> 여행", "<여행사> <지역> 패키지".

## 4. SEO 점검

```bash
python3 $S/seo_check.py $P/post.md --keyword "<메인>" --sub "<서브1>,<서브2>"
```
- "다른 글과 같은 문장", "반복되는 상투구"가 걸리면 그 문장을 새 표현으로 바꾼다.
- "수정 필요" 항목은 고친 뒤 다시 돌린다. "확인" 항목은 글이 어색해지지 않는 선에서만 맞춘다.
- 점수를 맞추려고 문장을 망치지 않는다. 사람이 읽기 좋은 글이 먼저다.

## 5. 사진 배치 미리보기 만들기

```bash
python3 $S/render_preview.py $P --link "<상품 링크>"
```
- `$P/preview.html`에 사진이 본문 제자리에 들어간 페이지가 만들어진다(본문/제목/태그/링크 복사 버튼 포함).
- Artifact 도구로 발행한다(처음엔 icon `document`, `capabilities: {"downloads": true}` — 사진 저장 버튼용).
- 네이버 앱은 복사한 사진을 받지 못한다(사용자 확인). 본문 복사에는 사진 대신 `📷 [사진 N] 여기에 photo_0N 넣기 · 캡션` 줄이 들어간다. 사용자는 '사진 N장 저장'으로 받은 사진을 그 자리에 넣는다. 결과 전달 때 이 순서를 안내한다. 같은 상품을 고칠 땐 같은 파일 경로로 다시 발행해 링크를 유지한다.

## 5.5 네이버 클립 영상 만들기 (링크를 받으면 기본으로 같이 만든다)

블로그 글과 같은 사실만 쓰는 25~30초 세로 영상(사용자 지시)(1080x1920)을 만든다. 쇼핑커넥트 스티커는 사용자가 클립 앱에서 직접 붙인다.

1. 장면 사진 고르기: 블로그 사진 4~5장 + 상세 이미지 2~3장, 모두 6~8장. `$P/clip/img/`에 긴 변 1400px로 저장한다.
   효과 %, 전후 비교, 순위·만족도 이미지는 쓰지 않는다. 모델(연예인) 얼굴이 크게 나온 사진도 피한다.
2. `$P/clip/clip.json` 작성(형식은 `scripts/make_clip.py` 맨 위 설명):
   - 장면 7~8개, 장면마다 `say`는 짧은 한 문장(12~25자). 전체 내레이션은 150~180자(공백 포함) = 약 25~30초. 만든 뒤 길이가 30초를 넘으면 문장을 줄여 다시 만든다.
   - 1번 장면은 2초 안에 걸리는 질문·숫자 훅("히터 살 때, 전기세부터 걱정되죠?"). 상품명은 2번 장면에.
   - `headline`은 화면 위 큰 글자(8~14자, 줄바꿈 1번까지), `highlight`는 자막에서 노랗게 칠할 숫자·핵심어.
   - 숫자는 읽히게 쓴다(33㎡ → "33제곱미터", 3.9kg → "3.9킬로그램"). 과장 금지. 단점 장면은 넣지 않는다. 조건이 있는 숫자는 조건만 짧게 붙인다(예: "절전 모드 기준 한 달 8천원대").
   - 마지막 장면: "할인가랑 이벤트는 쇼핑 스티커에서 확인하세요" 같은 안내(재촉하지 않기).
   - `upload`: 클립 제목(20자 안팎, 검색어 포함), 설명(대가성 문구 반드시 포함), 해시태그 4~6개.
   - 여행 상품은 장면 순서를 일정 순서로, 마지막에 "출발일별 가격은 쇼핑 스티커에서".
3. 실행: `python3 scripts/make_clip.py $P` (음성: edge-tts 신경망 음성. **기본은 사용자가 고른 fr-FR-VivienneMultilingualNeural(비비안, 여성), 속도 +15%(사용자 지시: 조금 빠르게)**. clip.json의 voice에도 이걸 쓴다. 다른 목소리는 사용자가 요청할 때만).
   edge-tts가 없으면 `pip install edge-tts`. 배경음은 스크립트가 직접 합성(저작권 문제 없음), 말할 때 자동으로 작아진다.
4. 확인: ffmpeg로 4~6개 시점의 프레임을 뽑아 Read로 보고, 글자가 사진·서로 겹치지 않는지, 자막이 말 단위로 자연스럽게 끊기는지 본다.
5. 전달: SendUserFile로 `clip.mp4`, `cover.jpg`, `upload.txt`를 보낸다. 올리는 방법을 짧게 안내한다:
   네이버 앱 → 클립 만들기 → 영상 선택 → 설명에 upload.txt 붙여넣기 → 쇼핑커넥트(쇼핑 스티커)로 상품 연결 → 유료광고 표시 켜기 → 업로드.

## 6. 결과 전달

1. 미리보기 링크를 맨 먼저 준다. SendUserFile로 `$P/post.md`와 `$P/photos/` 사진들도 보낸다.
2. 답변에는 아래만 짧게 정리한다.
   - 제목 후보 3개
   - 메인/서브 키워드와 고른 이유 한 줄
   - 태그
   - SEO 점검 결과 요약(통과 개수, 남은 "확인" 항목)
   - 발행 방법: 블로그 글쓰기(https://blog.naver.com/GoBlogWrite.naver) 열기 → 제목/본문 붙여넣기 →
     `[사진N]` 자리에 사진 넣기 → 맨 위 대가성 문구가 큰 글자·다른 색 상자로 보이는지 확인 → 👉 링크 안내 밑의 주소가 링크로 바뀌었는지 확인(글자로만 남았으면 주소 끝에서 엔터) → 태그 입력 → 직접 발행
   - 후기 메모 없이 썼다면: "써보신 느낌을 몇 줄 주시면 실제 후기로 다시 써 드릴게요."
3. `post.md`, `preview.html`, `keywords.json`, `product.json`, `style.json`을 커밋하고 푸시한다(`posts/*/photos/`는 .gitignore로 제외되어 있다).
