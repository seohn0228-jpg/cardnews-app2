# 네이버 쇼핑커넥트 블로그 원고 작성

사용자가 상품 링크를 주면 아래 순서대로 끝까지 진행한다. 중간에 확인을 묻지 말고,
막히는 단계만 대체 방법으로 넘어간다. 결과는 **발행 직전 원고**까지이고,
발행 버튼은 사용자가 직접 누른다(자동 발행은 네이버 어뷰징 정책 위반 소지가 있어 하지 않는다).

스크립트 경로: 이 파일이 있는 폴더의 `scripts/` (아래에서 `$S`로 표기).
스크립트에는 `requests`, `beautifulsoup4`가 필요하다. 없으면 `pip install -q requests beautifulsoup4`로 설치한다.
작업 폴더: 저장소 루트의 `posts/<YYYY-MM-DD>-<상품 짧은 이름>/` (`$P`로 표기).

## 0. 입력 확인

사용자 메시지에서 다음을 찾는다. 없는 것은 묻지 말고 기본값으로 진행한다.
- 상품 링크 (필수)
- 사용 후기 메모: 직접 써봤다면 느낀 점 몇 줄. **없으면 "알아본 사람" 시점으로 쓴다.**
- 직접 찍은 사진(업로드 파일): 있으면 상품 사진보다 우선해서 배치한다.
- 글 분위기: 기본값 "친근한 생활 블로거"

## 1. 상품 정보 가져오기

```bash
python3 $S/product_scraper.py "<링크>" --out $P
```
- 성공하면 `$P/product.json`과 `$P/photos/photo_NN.jpg`가 생긴다. 사진은 Read로 하나씩 열어서 실제로 무엇이 찍혀 있는지 확인한다.
- 실패하면 WebFetch로 같은 링크를 열어 본다.
- 그래도 실패하면(네트워크 차단 등) 사용자에게 **상세페이지 글 복사본과 사진 캡처를 올려 달라고 한 번만** 요청하고, 받은 것으로 계속한다.
  이 클라우드 환경에서 네이버가 막혀 있다면, 환경 설정의 Network access에 아래 도메인을 추가하면 된다고 안내한다:
  `naver.com`, `naver.me`, `pstatic.net`

정리할 것(사실만, 근거 없는 장점 금지): 상품명, 카테고리, 가격, 장점, 스펙(용량·크기·소재 등),
누구에게 맞는지, 구매 전 알아둘 점/아쉬운 점, 사진별로 보이는 내용.

## 2. 키워드 조사

```bash
python3 $S/naver_suggest.py "<씨앗1>" "<씨앗2>" "<씨앗3>"
```
- 씨앗 키워드: 상품 종류(예: 전동칫솔), 브랜드+종류, 핵심 특징+종류 등 2~4개.
- 결과의 `hits`(여러 질의에 나온 횟수)가 많고 `best_rank`가 앞일수록 실제로 많이 검색되는 키워드다.
- 자동완성이 막혀 있으면 WebSearch로 "<상품 종류> 추천", "<상품 종류> 후기"를 검색해 제목에 반복되는 표현을 모으고, 결과에 "추정 키워드"라고 표시한다.

고르는 기준:
- **메인 키워드 1개**: 2~3어절 롱테일 (예: "전동칫솔" 대신 "잇몸 약한 사람 전동칫솔"). 너무 큰 키워드는 상위 노출이 어렵다.
- **서브 키워드 3~4개**: 후기/비교/단점/가성비 같은 의도 키워드와 브랜드명.
- `$P/keywords.json`에 고른 이유와 함께 저장한다.

## 3. 원고 작성

`$P/post.md`에 아래 형식으로 쓴다.

```
# <선택한 제목>

이 포스팅은 네이버 쇼핑 커넥트 활동의 일환으로, 판매 발생 시 수수료를 제공받습니다.

<도입 문단>

[사진1]

## <소제목>
...

[상품 링크]

태그: #태그1 #태그2 ... (10개 안팎)
```

### 사람 냄새 나는 글 규칙
- 문장 길이를 섞는다. 짧게 끊는 문장 사이에 가끔 긴 문장을 넣는다.
- 블로그 구어체 "~더라고요", "~거든요", "솔직히", "이게 은근", "저만 그런 거 아니죠?"를 과하지 않게 쓴다.
- 첫 문단은 공감되는 상황이나 고민으로 시작한다. 상품 이름부터 들이밀지 않는다.
- 장점만 늘어놓지 않는다. 아쉬운 점이나 "이런 분께는 안 맞아요"를 하나 이상 넣어야 믿음이 간다.
- 받은 자료에 있는 구체적인 숫자(용량, 크기, 시간, 가격)를 섞는다.
- 문단은 2~4줄. 모바일 기준으로 줄바꿈을 자주 한다.
- 이모티콘은 글 전체에서 3~5개만 쓴다.
- 스펙 정리용 목록은 한 군데만 쓰고, 나머지는 문장으로 풀어 쓴다.

### 쓰지 말 것 (AI 티)
"오늘은 ~에 대해 알아보겠습니다", "결론적으로", "요약하자면", "~하는 것이 중요합니다", "다양한", "효과적인",
"완벽한", "혁신적인", "도움이 되셨기를", 모든 문단이 같은 길이와 구조인 글, "강력 추천" 반복.

### 정직하게 쓰기 (반드시 지킬 것)
- 후기 메모가 있으면 그 경험을 중심으로 1인칭으로 쓴다. **메모에 없는 경험은 지어내지 않는다.**
- 메모가 없으면 써본 척하지 않는다. "상세페이지를 꼼꼼히 봤는데", "후기들 보니까 공통적으로",
  "제가 이걸 고른 이유는"처럼 알아보고 비교한 사람 시점으로 쓴다.
- 자료에 없는 효능, 수치, 수상 경력, 판매량은 만들지 않는다. 건강이나 의학 효과를 단정하지 않는다.
- 대가성 문구는 본문 맨 위에 항상 넣는다(공정위 추천·보증 심사지침).

### 검색 노출 규칙
- 제목: 메인 키워드를 앞쪽에 넣고 20~40자로 쓴다. 궁금증, 비교, 숫자, 솔직함 중 하나로 후킹한다. 거짓 낚시 제목은 금지. 후보 3개를 만들고 가장 좋은 것을 `# `에 쓴다.
- 메인 키워드: 첫 문단에 1번, 본문 전체에 4~6번. 억지로 반복하지 않는다.
- 서브 키워드: 소제목과 본문에 1~2번씩 나눠 넣는다.
- 본문: 공백 포함 1,800~2,500자, 소제목(`## `) 4~6개.
- 사진: 본문 사이사이에 고르게, 설명하는 내용 바로 옆에 둔다. `[사진N]`의 N은 `$P/photos`의 파일 번호다.

## 4. SEO 점검

```bash
python3 $S/seo_check.py $P/post.md --keyword "<메인>" --sub "<서브1>,<서브2>"
```
- "수정 필요" 항목은 고친 뒤 다시 돌린다. "확인" 항목은 글이 어색해지지 않는 선에서만 맞춘다.
- 점수를 맞추려고 문장을 망치지 않는다. 사람이 읽기 좋은 글이 먼저다.

## 5. 결과 전달

1. SendUserFile로 `$P/post.md`를 보낸다.
2. 답변에는 아래만 짧게 정리한다.
   - 제목 후보 3개
   - 메인/서브 키워드와 고른 이유 한 줄
   - 사진 배치표: `[사진N]` → 어떤 사진 → 사진 아래 캡션(키워드를 자연스럽게 포함)
   - 태그
   - SEO 점검 결과 요약(통과 개수, 남은 "확인" 항목)
   - 발행 방법: 블로그 글쓰기(https://blog.naver.com/GoBlogWrite.naver) 열기 → 제목/본문 붙여넣기 →
     `[사진N]` 자리에 사진 넣기 → `[상품 링크]` 자리에 쇼핑커넥트 링크 넣기 → 태그 입력 → 직접 발행
   - 후기 메모 없이 썼다면: "써보신 느낌을 몇 줄 주시면 실제 후기로 다시 써 드릴게요."
3. `post.md`와 `keywords.json`, `product.json`을 커밋하고 푸시한다(`posts/*/photos/`는 .gitignore로 제외되어 있다).
